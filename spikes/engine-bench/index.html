All times are wall-clock ms on this machine, from "render page N" until the pixels are on a canvas — what you'd feel as a reader. Engines run one after another, never at the same time. Longest UI freeze = the biggest gap in a 16 ms heartbeat while that engine ran (the green dot above stutters when the page is frozen). pdf.js parses in a worker; MuPDF and PDFium here run on the main thread, so their freeze ≈ their render time — in a worker it would drop to ~0. New page = first time each page is drawn (reading forward) — the column that matters most. Re-render = same page again (zoom, night-mode toggle); pdf.js caches parsed pages there, the other two adapters re-parse (they could cache too). MuPDF's time includes a JS RGB→RGBA copy a real integration would skip. Ships = gzip size of the production engine files. Init is only cold on the first run after page load — reload the tab to re-measure it.
